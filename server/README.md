# Stillframe 群晖相册服务器

Stillframe 服务端管理照片、多级分类、墨水屏设备与播放配置。设备首次请求自动建档，返回 default 配置；以后每次取图同时获取当前配置。程序提供真实服务接口和持久化存储，不是网页模拟器。

当前版本 0.1.30。优先采用与现有 nes-emulator 资料库服务相同的 DSM 7 原生 SPK 部署方式，使用独立套件 **Stillframe**、系统用户、数据目录和 **8484** 端口，不修改 FCEmulatorLibrary 或其 8282／8383 服务。也提供 Docker 部署文件。

## 已实现功能

- 首次创建管理员，密码哈希存储，登录会话与设备凭证分离。
- 设置页修改管理员密码，验证当前密码并确认新密码；旧会话失效，当前页面获得新会话，设备凭证不变。
- 多级分类的新增、改名、移动与删除；拒绝循环嵌套和删除非空分类。
- 批量上传 JPG／PNG，单张最多 20 MB、2400 万像素；按原图 SHA-256 去重。
- 照片改名、分类调整、启停与删除，支持原图和六色预览。预览按内尺寸 30 × 45 cm、开窗 20 × 26.8 cm 的原木画框和白色卡纸装裱，模拟边缘遮挡。
- 图片完整保留或居中裁切，支持 0／90／180／270 度旋转及六色抖动。
- 自动生成 1200 × 1600 显示数据，每张 960000 字节，附 SHA-256。
- default 配置，以及每台设备的专属分类、刷新间隔和顺序／随机播放设置。
- 设备自动注册、固定身份、最后请求时间、设备报告的当前照片与可选固件／电量信息。
- 请求幂等与显示确认：下载未完成时重试同一张，不直接跳到下一张。
- 接入凭证查看与更换、设备停用、最近活动记录。
- 私有数据原子落盘，写入前一版本备份、单实例锁、重启恢复；数据损坏时拒绝启动而非静默清空。

## DSM 安装

构建产物在 [dist/Stillframe-0.1.13-0014.spk](dist/Stillframe-0.1.13-0014.spk)。

1. 在群晖套件中心安装 Node.js v22 或 v20。最低兼容版本为 Node.js 18.17。
2. 套件中心选择“手动安装”，选择 Stillframe SPK。
3. 安装并启动后，打开 DSM 菜单中的 Stillframe，或访问 `http://群晖地址:8484/`。
4. 首次使用创建管理员；服务没有预设管理员密码。
5. 上传照片，设置默认分类和刷新间隔。
6. 在“相框设备 → 连接新相框”查看服务器地址和设备接入凭证。

配网时，设备应填写它能访问的群晖 IP／域名及 8484 端口，不能填写 localhost 或 127.0.0.1。管理页面与设备接口使用同一个服务地址。当前按根路径部署；反向代理应转发到根路径，并允许至少 30 MB 请求体和约 90 秒处理时间。若通过 HTTPS 反向代理访问，建议统一从该地址使用，避免混合访问。

管理员首次初始化通过网页进行，应先在可信局域网中完成。此版本使用一份共享设备接入凭证；它允许持有凭证的设备按标识注册并取图，不能当成每台设备独立的强身份认证。停用设备拒绝其同步请求；如凭证泄露，应在设置中更换全部设备使用的凭证。

此 SPK 尚未在 DSM 实机安装验收。已检查套件两层结构、INFO 校验和、生命周期脚本权限、启动入口、依赖、DSM 图标及端口。没有连接群晖、安装套件或修改现有服务。

## 本机运行

```sh
cd server
npm ci
npm start
```

打开 `http://127.0.0.1:8484/`。默认仅监听本机。

可设置以下环境变量：

| 变量 | 默认值 | 说明 |
|---|---|---|
| STILLFRAME_HOST | 127.0.0.1 | 本机仅回环；群晖套件设置为 0.0.0.0 |
| STILLFRAME_PORT | 8484 | HTTP 服务端口 |
| STILLFRAME_DATA_DIR | server/data | 原图、派生图片、设备和配置数据 |

当前自动化环境禁止端口监听，因此本次通过内存 HTTP 请求驱动真实服务处理函数完成接口测试，没有声称完成本地浏览器或真实 HTTP 端口联调。

## 数据与备份

DSM 数据位于 `/var/packages/Stillframe/var/data`，日志为 `/var/packages/Stillframe/var/stillframe.log`。程序文件位于 target，升级时不把运行数据打回程序包。

备份步骤：停止 Stillframe，备份整个 data 目录，再启动。目录内包含设备接入凭证和管理员密码哈希，应只让管理员访问。恢复时停止服务并恢复完整目录。`state.json.previous` 是上一次成功更新前的快照，只包含元数据，不能单独替代照片文件备份。发现主状态文件损坏时，服务不会自动切换旧快照，避免意外回退设备和安全配置，应先保留原文件后手工恢复。

每次图片重新处理会生成新版本文件，旧版本保留，以免设备正在下载时哈希变化。当前不自动清理照片的旧派生版本；删除照片会删除整张照片的所有文件。统计中的显示数据是当前版本总量，不是整个数据目录的磁盘占用。

另用临时 happy-dom 测试环境运行了真实页面脚本，并连接同一后台处理函数，验证首次创建管理员、页面导航、新增分类、保存 default 配置、设备改名和专属配置、凭证显示、修改管理员密码及退出登录，并检查实体画框预览结构。测试入口为 test/ui-smoke.mjs，临时 DOM 依赖未打入产品。这是 DOM 交互验证，不等于真实浏览器渲染和网络端口联调。

## Docker

```sh
cd server
docker compose up -d --build
```

compose 使用独立命名数据卷，可按实际群晖数据卷改为专用目录挂载；挂载目录需允许容器 node 用户（UID 1000）读写，不要放宽整个共享目录的权限。Dockerfile 支持 Node 官方镜像提供的 CPU 架构；本次没有 Docker 运行环境，镜像构建与容器启动尚未实测。

## 当前边界

- 不提供实际 ESP32 固件烧录、OTA 固件分发或本地 SD 卡管理。
- 照片导入当前支持 JPG、PNG；不支持 WebP、HEIC 和动态图片。JPEG 的 EXIF 方向不自动应用，可通过照片编辑手工旋转。
- 六色预览使用近似颜色，不代表墨水屏实测色彩；完整显示链仍需上屏验证。
- 不会在群晖文件系统中任意扫描用户目录；照片通过管理页面明确上传。
- 默认配置被设备持续继承，直到管理员为它保存一份完整专属配置；专属配置不再跟随 default。可以恢复继承。
- 页面和接口已完成实现，真实浏览器交互、DSM 安装、跨版本升级和真实设备联网仍待实际环境验收。

设备接口见 [API.md](API.md)。

设备卡片的空画框改为照片预览，并可点击放大。优先展示设备报告正在显示的照片；尚无显示报告时，展示最近下载，标为“待确认显示”。同时分别列出设备报告显示、最近下载与下载时间，可展开最近 20 次下载记录。版本化预览保留实际下载时的画面，照片删除后保留记录并显示不可预览，不使用其他照片替代。

下载地址自动附带设备身份，兼容现有 ESP32 固件，不需要因该功能重新刷 ROM。服务器只在完整 GET 发送结束后记录下载；不会把下载记录当成屏幕显示成功。HEAD、权限错误、缺失文件、停用和响应中断不计入记录。旧状态文件无需迁移；旧缓存响应自动补齐归属参数。

本次 9 组后端测试及 DOM + 真实后台交互测试通过，涵盖完整/中断下载、历史版本、20 条上限、重启持久化、待确认/设备报告状态、点击放大和删除照片。`Stillframe-0.1.4-0005.spk` 已完成包结构验证；需要在 DSM 安装新版，在线群晖页面才会更新。

ROM 管理入口在「设置 → ROM 管理」，上传 Stillframe.bin 后在「相框设备 → 升级 ROM」手动下发。服务器会在上传、下载和下发时核对文件、主板、屏幕、芯片、分区容量及 SHA-256；旧固件型号未知时拒绝下发。详见 [API.md](API.md) 的 ROM 管理章节。
