# Stillframe 群晖联调与看门狗修复

日期：2026-10-24。当前版本：**0.1.1-rc5，修复候选，尚未通过实机验证**。0.1.0 已撤回，旧包移至 `firmware/dist/known-bad-0.1.0`，不可作为可刷写版本使用。下文 rc1～rc4 为按时间保留的过程记录。

## 发现的问题与修复

用户实际运行后，在约 60 秒触发工作任务看门狗。之前的启动测试只覆盖到服务启动，核心集成测试使用屏幕替身，未覆盖真实驱动里的无限等待；此前将其描述为“完成”过早。

真实驱动卡在控制器 0 的第一条 `0x74` SPI 指令。`spi_device_transmit()` 内部无限等待，原先的 120 秒限制只覆盖 BUSY 信号，没有覆盖 SPI 完成事件。

修复为有时限的 `spi_device_queue_trans()` / `spi_device_get_trans_result()`，两处分别最多等待 3 秒。超时后关闭屏幕供电并隔离此 SPI 总线，直到重启；不会关闭看门狗，也不会由另一任务代替卡住的任务喂狗。

为防止超时后 DMA 仍然运行，事务描述符与 300 字节 DMA 缓冲区使用静态存储。总线隔离后不再覆盖它们，避免迟到的 DMA 访问已经返回的栈或被复用的数据。所有初始化指令和每行发送都经过这条有界路径。

增加独立的屏幕错误状态；设置页面持续显示屏幕故障信息。屏幕出错不再被误报成群晖不可用，网络设置和 OTA 可以继续使用。

## 真实驱动回归

`CONFIG_SF_RUNTIME_TEST` 是独立的测试选项：使用真实工作任务与真实驱动，**没有屏幕替身**。模拟器缺少该屏的响应，实际触发 SPI 超时，然后每 10 秒请求设备 HTTP 状态并检查操作锁可获得。

本次检查持续至设备运行约 **97 秒**，超过原来约 60 秒的故障点；HTTP 和工作任务正常，日志出现 `REAL DRIVER RUNTIME TEST PASSED`。完整运行 110 秒正常退出，没有看门狗故障。可复现入口为 `firmware/tools/test-emulator.sh`。

后续完整回归也通过：配置重启保留、JSON 正反例、完整 HTTP 取图、哈希错误和截断拒绝、认证、实际网页 OTA、故意启动崩溃后的引导程序回退。其中包含真实群晖配置与真实莫奈显示文件的 ESP32 指令级解析/校验。

- `firmware/test-results/safety-replay.log`：完整安全回归，包含预期崩溃和成功回退。

rc7 继续处理供电、屏幕故障和恢复路径，发布目录与 rc6 分开，避免同一版本名对应不同二进制。
