# Stillframe 固件开发与仿真测试

> **状态更正：0.1.0 已撤回，不应用于刷写。** 当前修复候选为 0.1.1-rc7，完整仿真回归通过；尚未完成实机验证。早期候选的过程记录保留在本文和联调文档中。


日期：2026-10-24。首版固件：0.1.0。目标硬件：ESP32-133C02-IL / ESP32-S3 N16R8、GDEP133C02 1200 × 1600 六色屏。

本次编写了 ESP-IDF C 固件，构建了实际应用 bin 与从地址 0 启动的合并 Flash 镜像，并在 Espressif ESP Emulator 中执行 ROM、IDF 引导程序和应用。未刷写真实设备，未修改群晖在线服务。

## 已开发

- 首次开机使用向日葵引导图，附 Stillframe 热点、初始密码、访问地址与可解码二维码；帮助文字以黑白输出，画作区域六色抖动。
- Wi-Fi AP + 手机网页配置。保存家庭 Wi-Fi、服务器地址、设备凭证与热点密码；首次配置前和配置后，所有网页及管理接口都要求 admin / 当前热点密码登录。手机热点自动弹窗对 HTTP Basic 登录框的兼容性仍需 iOS、Android 实机验证，必要时改用系统浏览器。基础字段校验、Wi-Fi 或存储失败不覆盖旧配置；服务器不可用或凭证错误由同步任务报告并重试，可回到设置页修改。
- NVS 保存配置与稳定设备身份；初始化失败不自动擦除。成功显示之后才保存照片 ID，下一次同步请求才确认已显示。
- 真实服务器 JSON 同步接口、每次同步读取新配置、完整二进制下载、长度/颜色编码/SHA-256 校验、同源下载限制、失败退避与画面保留。
- GDEP133C02 双控制器 SPI 驱动。按每行前后各 300 字节分别发送；BUSY 等待上限 120 秒，定期喂看门狗；完成或失败时关闭屏幕电源。
- 最短 180 秒刷新限制；开机引导图之后，首次照片可能等约 3 分钟。配网完成后下一次画面刷新不再显示帮助密码。重启期间继续保留墨水屏原有画面。
- MicroSD 检测、显式切换本地模式、本地照片上传/预览/删除、多级分类维护、分类播放、顺序/随机、存储容量显示。浏览器负责图像缩放、居中裁切、六色抖动和打包。
- 两个各 5 MiB 的 OTA 应用区。网页上传应用 bin；验证芯片、应用标识与 SHA-256，写完才切换启动分区。升级确认后暂停照片任务，关闭屏幕供电并重启；启动自检失败由引导程序回退。
- SW4 长按 5 秒重新开启配置热点，不清空设备身份。
- 连续三次早期复位进入安全模式；可长按 SW4 退出，或稳定运行 30 分钟后自动重试。刷屏中途复位累计三次后停止自动刷屏，要求检查供电并断电恢复。
- PSRAM 不足时暂停照片播放，但保持管理网页和固件升级可用。OTA 仅在升级前屏幕有成功刷新记录时，才因新程序首次刷屏失败而回滚。

配置保存、服务器同步、驱动、网页与本地存储分开编写，源码见 [firmware/main](../firmware/main)。使用和构建方法见 [firmware/README.md](../firmware/README.md)。

## 仿真环境

- ESP-IDF v5.5.2，提交 `30aaf64524299d3bde422ca9a2848090d1bc5d0f`。
- Xtensa GCC esp-14.2.0_20251107；工具归档 SHA-256 已核对，详见 [sdk-lock.json](../firmware/tools/sdk-lock.json)。
- Espressif ESP Emulator Beta 0.50.0，ESP32-S3、8 MiB PSRAM，从真实 ROM 启动，未跳过引导程序。
- 正式构建关闭 `CONFIG_SF_TEST_MODE` 和 `CONFIG_SF_TEST_PANIC`，并扫描发布应用确认不含测试屏幕替身或故意崩溃入口的标志字符串。

宿主环境禁止模拟器建立本机监听端口，也拒绝其连接 `10.10.10.21:8484`。因此 HTTP 集成测试在**模拟器内部的 TCP 回环接口**建立独立测试服务器。执行 HTTP 的仍是编译后的 ESP32-S3 固件和 IDF 网络栈。此结果不代表真实 NAS 联网已经验证。

## 测试结果与证据

| 测试 | 结果与范围 |
|---|---|
| 正式固件启动 | ROM → 引导程序 → Stillframe，NVS、8 MiB PSRAM、SPI 总线、Wi-Fi、HTTP 与任务创建成功；日志出现 `SELFTEST PASS` |
| AP | 初始 WPA2 热点启动，模拟器客户端获取 `192.168.4.2`；重启后 SDK AP 配置使用已保存的新密码 |
| 重启保留配置 | 实际 NVS 写入后执行 `esp_restart()`，验证 Wi-Fi、热点密码、间隔、配置状态与设备身份保持一致；升级失败回退之后再次检查 |
| JSON 校验 | 默认/更新配置、空相册、缺失字段、错误尺寸、跨域图片地址、过短间隔等通过正反例检查 |
| 完整 HTTP 取图 | 测试服务器向真实 IDF 客户端发送 960000 字节图像，固件校验 SHA-256 后交给测试屏幕入口 |
| 每次读取新配置 | 连续三次请求读取 180 / 7200 / 900 秒设置；第三次无新图仍应用新间隔 |
| 显示确认与重试 | 模拟屏幕失败时不确认照片，下次请求复用 requestId；模拟成功后才在后续请求确认该照片 |
| 下载异常 | HTTP 截断、大小不符、不支持的颜色编码、哈希错误、401 均不提交新画面；原照片确认 ID 保留 |
| 管理接口 | 首次配网前和配置后，首页、状态、配置、本地存储、刷新和 OTA 未认证访问均得到 401；正确认证获得状态，返回内容不含 Wi-Fi 密码、热点密码或设备凭证；短热点密码被拒绝 |
| 供电/屏幕恢复 | 三次刷新中复位后停止自动刷屏；已知健康屏幕在待确认新程序中失败会回滚，升级前已故障则保留修复版 |
| 安全模式恢复 | 长按 SW4 或稳定 30 分钟后重试；自动重试在模拟器中确认等待占用中的写操作释放 |
| 缺卡 | 模拟器的 SD 初始化失败；不启用本地相册，不自动格式化或切换来源 |
| 错误 OTA 校验值 | 通过真实网页升级 HTTP 接口上传，返回 400，启动分区保持原值 |
| 有效 OTA | 同一 HTTP 接口接收有效 Stillframe 测试应用，写入备用区并自动重启 |
| 实际启动失败回退 | 新应用故意在标记有效之前崩溃；关闭模拟器的提前拦截，让真实引导程序再次启动；最终回到 ota_0，ota_1 状态为 ABORTED |
| 正常新版本确认 | 将正式应用以 NEW 状态放入 ota_1，实际启动后由正式代码确认有效；读取保存的 Flash 元数据，状态为 VALID（2） |
| 浏览器脚本 | JavaScript 语法检查；HTTP 环境可用的 SHA-256 实现与 Node 标准实现对照 6 组输入，包括完整 960000 字节图像 |
| 引导二维码 | 用 jsQR 1.4.0 对实际六色预览解码，结果严格等于 `http://192.168.4.1/` |

## 仿真边界和后续实机验证

模拟器没有此型号墨水屏的外设模型。集成测试使用**仅测试构建存在的屏幕替身**，分别返回成功与超时，验证上层流程、请求确认和异常处理。正式固件完全使用硬件驱动；正式启动日志证明初始化和服务启动，不能证明真实屏幕完成刷新。模拟器中的正式固件会等待未建模的 BUSY 信号，不能据此判断真实屏幕的刷新效果。

尚需真实设备确认：屏幕接线、电平与时序、完整数据发送、BUSY 超时与断电行为、颜色与扫码效果、MicroSD 真实读写/插拔/掉电恢复、SW4 电平与长按、手机完整配网、与实际群晖的端到端通信。HTTPS/SNTP 已接入但未实测。服务端接口、NVS 与 OTA 的模拟测试不能替代这些硬件测试。

本次模拟器的正常退出会保存 Flash。已验证的是重启和升级故障后的持久化；没有验证物理断电时存储卡或 Flash 芯片所有可能的中间状态。
