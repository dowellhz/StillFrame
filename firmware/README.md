# Stillframe ESP32 固件 0.1.1-rc17（修复候选）

> **状态更正：0.1.0 已撤回，不应用于刷写。** 当前修复候选为 0.1.1-rc17，已在实体 ESP32-133C02-IL 开发板上完成配网、群晖同步、完整刷屏和网页 HTTP OTA 验证。


面向 Good Display ESP32-133C02-IL / ESP32-S3 N16R8 与 GDEP133C02 13.3 英寸六色屏，使用 ESP-IDF 5.5.2。源码可以编译成真实 ESP32-S3 程序；已在 Espressif ESP Emulator 0.50.0 中执行。

## 使用

首次开机连接手机 Wi-Fi：**Stillframe**，初始密码 **12345678**。保持连接，即使手机提示“无互联网”。连接后扫码，或在浏览器打开 **http://192.168.4.1/**。首次进入网页也需要登录：用户名 **admin**，密码 **12345678**（与当前热点密码相同）。

填写家庭 Wi-Fi、相册服务器地址（例如 `http://10.10.10.21:8484`）、服务器设置页中的**设备连接凭证**。这里不填群晖或相册管理员的登录密码。留空的已保存密码和凭证保持原值；更换 Wi-Fi 名称并留空密码表示开放网络。

配置校验通过后写入 NVS，重启会恢复。配置不会因 NVS 初始化出错被自动擦除。设备身份由芯片 MAC 生成并保存。基础字段校验、Wi-Fi 连接或存储失败时保留原设置，可重新填写。服务器地址与凭证保存后由同步任务使用；服务器不可用或凭证被拒绝时保留配置并重试，可长按 SW4 回到设置页修改。

服务器模式配网成功后关闭热点。长按板上 **SW4 / GPIO14 约 5 秒**可重新开启热点，不清除身份和配置。首次配置前和配置后的管理页面都要求登录；用户名是 **admin**，密码与设置热点密码相同。可在网页更改热点密码。密码与设备凭证不通过状态接口返回。手机热点自动弹窗能否可靠显示 HTTP Basic 登录框，仍需分别用 iOS 和 Android 实机确认；若自动弹窗不能登录，请使用系统浏览器打开上述地址。

配网完成后，下一次刷新换成照片，不再显示引导密码。为遵守刷新间隔，首次照片可能需要等约 3 分钟；之后按服务器配置刷新，手动刷新也受最短 180 秒间隔限制。首次开机内置向日葵和二维码，无照片时保留原画面。服务器暂不可用会退避重试，不清空配置或画面。

本机管理页面使用局域网 HTTP。HTTPS 服务器地址会启用证书校验与 SNTP 校时，需能访问校时服务；本次接口仿真使用 HTTP，HTTPS/SNTP 尚未实测。

## 本地相册

不插 MicroSD 时只有服务器模式。插入已格式化的 FAT 存储卡，启动时检测，或点“重新检测 MicroSD 卡”，再手动选择本地相册。检测失败不格式化存储卡，也不自动改变播放来源。

网页可上传、预览和删除照片；建立多级分类、改名和删除空分类；选择播放分类、顺序/随机和刷新间隔。所选分类包含子分类。浏览器将图片铺满画面、居中裁切，并完成六色抖动转换，再传送 960000 字节显示文件到卡。无需把照片写进内部 Flash。

卡内目录为 `/stillframe`，包含 `index.json`、备份索引与各照片的 `.bin` 文件。索引先写临时文件，再保留旧索引并切换；启动读取索引时可回退到备份。不等同于保证 FAT 在任意掉电时均不损坏。存储卡插拔与真实读写仍需实机确认。

## 固件文件

`dist` 中仅放正式构建，测试故障固件不放在这里。

| 文件 | 用途 |
|---|---|
| `candidate-0.1.1-rc17/Stillframe-0.1.1-rc17-flash.bin` | 首次有线写入、模拟器启动，从地址 0 开始的合并镜像 |
| `candidate-0.1.1-rc17/Stillframe-0.1.1-rc17-app.bin` | 已运行 Stillframe 后，通过设备网页或群晖进行 OTA 升级 |
| `candidate-0.1.1-rc17/Stillframe-0.1.1-rc17.elf` | 符号与调试文件 |
| `SHA256SUMS` | 发布文件的 SHA-256 校验值 |

网页会计算应用 bin 的 SHA-256。固件在备用分区校验长度、ESP32-S3 芯片标识、Stillframe 应用描述与完整 SHA-256；成功后才切换下次启动分区。校验失败继续使用当前程序。

新程序确认 NVS、Wi-Fi、HTTP 服务以及任务创建成功后标记有效。PSRAM 不足时暂停照片播放，但管理网页和固件升级继续可用；处于待确认的新程序则回滚。外部服务器离线不会触发误回退。启动检查前崩溃会由 IDF 引导程序回到旧程序。只有升级前存在成功刷屏记录时，新程序首次刷屏失败才归因于新程序并触发回滚；屏幕原本已坏时保留新程序，允许安装修屏版本。

首次安装 Stillframe 涉及分区表变化；应先备份原厂固件与配置。此目录的脚本不自动连接或刷写真实设备。有线引脚与供电仍以实际板卡及原厂资料为准。

## 构建

当前工作区已安装固定版本工具链，根目录执行：

```sh
firmware/tools/idf.sh build merge-bin
```

其他环境安装 ESP-IDF **v5.5.2** 并执行其 `export.sh` 后，在 `firmware` 目录使用 `idf.py set-target esp32s3`、`idf.py build merge-bin`。正式构建必须关闭 `CONFIG_SF_TEST_MODE` 和 `CONFIG_SF_TEST_PANIC`。默认关闭，可运行 `python3 firmware/tools/variant.py release` 恢复工作区的正式配置。

工具链版本及校验值见 `tools/sdk-lock.json`；Python 依赖快照见 `tools/python-requirements.lock`。`tools/idf.sh` 是当前 Mac 工作区的便捷入口，不替代跨平台 ESP-IDF 官方安装流程。启动图预先生成并随源码提供，不需要每次构建重新生成。

重新生成图片资源，在项目根目录执行：

```sh
swift -module-cache-path /private/tmp/stillframe-swift-cache firmware/tools/setup-art.swift
node firmware/tools/make-assets.mjs
```

此步骤使用 macOS AppKit 和服务器目录中的图像转换依赖。二维码来自既有配网二维码；已对实际六色启动预览解码，内容为 `http://192.168.4.1/`。

## 仿真与检查

```sh
python3 emulator/run.py firmware/dist/candidate-0.1.1-rc17/Stillframe-0.1.1-rc17-flash.bin \
  --name stillframe --ap-password 12345678 \
  --elf firmware/dist/candidate-0.1.1-rc17/Stillframe-0.1.1-rc17.elf --seconds 30
node firmware/tools/web-test.mjs
```

实际 ROM、IDF 引导程序和 Xtensa 应用均参与执行。模拟器存档保存在 `emulator/runs/<name>/flash.bin`，不改输入文件。`--fresh` 清除该模拟设备原来的存档。

完整回归执行 `firmware/tools/test-emulator.sh`。测试先检查锁定的 ESP-IDF 补丁，运行热点报文解析、真实 SPI 超时、恢复网页、启动卡死回滚、HTTP/NVS/OTA 等用例；完成后恢复正式配置并重新构建。测试应用拥有单独的测试入口和**明确的屏幕替身**；正式固件无此替身。不要将 `test-assets` 的镜像刷到真实设备。

工具沙箱限制模拟器监听本机端口和连接 NAS；自动回归使用模拟器内 TCP 回环服务器，仍执行真实 IDF HTTP、JSON、完整图像下载、SHA-256、NVS 和 OTA。此前从普通 Terminal 启动已完成真实群晖连接、浏览器管理和网页 OTA。真实屏幕光学效果、BUSY 时序、MicroSD、硬件按钮和功耗仍未完成实机验证。具体证据见 [测试记录](../doc/Stillframe固件开发与仿真测试-2026-10-24.md)。

## 硬件与存储

| 用途 | 引脚 |
|---|---|
| 屏幕 SPI3 CLK / MOSI / MISO | 9 / 41 / 40 |
| 屏幕 CS0 / CS1 | 18 / 17 |
| BUSY / RESET / LOAD_SW | 7 / 6 / 45 |
| MicroSD SPI2 CLK / MOSI / MISO / CS | 8 / 3 / 5 / 15 |
| 设置热点按键 SW4 | 14，外部上拉，按下为低电平；**本板未焊 SW4**，改由断网自动开热点 |
| 禁用引脚 | GPIO12、GPIO13 不得配置；GPIO13 开内部下拉约 10 秒后会触发掉电复位 |

屏幕每行 600 字节，两控制器分别接收每行的前/后 300 字节。像素高半字节在前，仅允许 0/1/2/3/5/6 六个颜色编码。BUSY 等待有 120 秒上限，并定期喂看门狗；失败关闭屏幕电源，正常刷新后也关闭高压驱动。

rc6 起按厂商示例调整 PON / DRF / POF 期间的双 CS 时序，并移除逐行 1 ms 忙等。一次屏幕通信故障后等待安全间隔并自动重启恢复；刷屏中途掉电复位或通信故障累计三次后停止自动刷屏，保持管理网页可用，并提示检查供电后断电重启。所有自动重启与长按 SW4 重启都会先等待 OTA、配置保存和 MicroSD 写入结束。

Flash 分区为 24 KiB NVS、8 KiB OTA 元数据、4 KiB PHY、两块各 5 MiB 应用区，余下 5.875 MiB 预留数据区；应用从 `0x20000` 开始。本版照片在 PSRAM 中校验后刷新，内部预留区尚不承担相册存储。每次成功刷新后才保存照片确认 ID，下一次取图请求才向服务器确认已显示。

最新修复、真实群晖连接和网页 OTA 记录见 [群晖联调与看门狗修复](../doc/Stillframe群晖联调与看门狗修复-2026-10-24.md)。


## 群晖下发 ROM 与省电（rc2）

群晖服务器 0.1.5 可在「设置 → ROM 管理」上传 app.bin，在指定设备卡片选择「升级 ROM」。应用包含固定位置硬件描述，自动报告主板 ESP32-133C02-IL、ESP32-S3、GDEP133C02、升级协议和备用分区容量。服务器和设备分别核对，测试 ROM（flags 非零）、整片 Flash 镜像及未知主板不可下发。设备校验文件长度、SHA-256 与 ESP-IDF 镜像后才切换启动分区；新版本启动失败由引导程序回退。每个任务一次尝试记录保存在独立 sf_ota NVS 命名空间，回退后拒绝再次刷入同一任务。

设备启动后计算当前分区完整应用文件 SHA-256，服务器据此确认成功。只更新应用，不改变引导程序、分区表、相册或配置布局。旧固件可先通过设备网页或有线更新兼容版本，随后使用群晖下发。物理商品型号无法仅靠 ESP32 芯片自动探测，硬件描述代表固件编译目标。

默认刷新 3600 秒，服务器配置立即获取，只有屏幕刷新操作遵守 180 秒保护。空闲采用 Wi-Fi MAX_MODEM、3 个 beacon 监听间隔，服务器同步阶段使用 MIN_MODEM；心跳改为 5 分钟，空闲轮询改为 500 ms。屏幕总线隔离后停止重复下载照片。当前没有启用深度睡眠，管理与恢复入口继续保留；实际节电量需真机测量。

模拟器 --seconds / --timeout 是电脑上的运行时限，退出会保存模拟 Flash，与固件请求超时、屏幕通信超时或看门狗不同。ROM 没有 30 分钟退出限制。

rc3 已在真实群晖 0.1.5 完成端到端分发验收，并修复“重启后过早显示升级成功”。启动待验证阶段不报告新 ROM 哈希，标记有效后立即同步，服务器再显示成功。详情见测试记录补充。

rc6 将启动确认延后到工作任务已就绪；已配网设备还需完成一次同步/下载/刷屏路径，未配网设备不再等待耗时的引导画面。连续三次在稳定点之前重启会进入安全模式并开启管理热点；从安全模式成功写入 OTA 后会清除旧失败计数，让新固件重新接受独立健康检查。远程 ROM 安装失败不再阻塞照片和服务器配置；OTA 改为边写边擦并使用堆缓冲。Wi-Fi 意外断线会立即安排重连，MicroSD I/O 故障会卸载并允许重新检测；相同照片 ID 和显示数据哈希不再重复下载、刷新。

rc7 允许长按 SW4 退出安全模式，并在安全模式稳定运行 30 分钟后自动尝试一次正常启动；两条路径都等待正在进行的写操作。刷屏中途复位累计三次后停止自动刷屏。PSRAM 不足不会再直接崩溃，而是暂停播放、保留网页与升级。OTA 的屏幕失败回滚以升级前已有成功刷新记录为前提，使屏幕故障修复版仍能安装。首次配置前后所有网页及接口均要求 admin 与当前热点密码登录；手机配网自动弹窗兼容性仍需 iOS 和 Android 真机验证。

## rc11 实机结论（2026-10-24）

厂家手册称 SW2～SW4 “高电平触发”，与本板实测不符：GPIO12/13/14 空闲均为高电平（外部上拉）。旧固件给三者开启内部下拉后，GPIO13 被拉低约 10 秒即出现 `Brownout detector was triggered`（低于 2.44 V）并复位；同一电源下原厂 WiFi 固件稳定。逐项排除（不开 WiFi、跳过 SD、屏幕引脚、按键，再逐个加回，逐个引脚单独下拉）确认只与 GPIO13 下拉有关。此前的浅黄画面是刷屏约 11 秒时被该复位打断，并非屏幕电流所致。旧固件还把 SW4 判反，开机 5 秒即误判长按并重启热点，造成手机断线。

rc11 只配置 GPIO14 且不开内部上下拉，低电平计为按下；开机时已为低电平的需先松开才计数。配置页把保存结果显示在按钮下方并指明具体字段，不再被 5 秒状态轮询覆盖。实机：完整刷屏约 27 秒无复位；rc10 → rc11 经设备网页 `/api/update` 上传 2,978,080 字节约 12.5 秒，重启后首个周期完成即标记有效，配置保留。

rc12 在刷屏成功后立即调用服务端 `POST /api/v1/device/displayed` 确认当前显示的照片，群晖“设备报告显示”与预览不再比实际屏幕落后一次同步（需群晖 0.1.7）。确认失败只记录警告，下一次 sync 仍照常上报。

rc14～rc16：两次刷新之间自动浅睡眠，刷屏后 1 秒关闭屏幕电源；开机期间与插着电脑时保持清醒以保住 USB 串口。本板没有 SW4，连续连不上家里 Wi-Fi 超过 `offlineHotspotSeconds`（默认 600 秒，由群晖 0.1.8 下发并存于 NVS 键 `offline_ap`）即自动打开设置热点，恢复连接后关闭；有设备连着热点时暂停重连。实机已验证浅睡眠下按时刷新、热点在首个周期后关闭；断网开热点路径尚未实机断网验证。

rc17 新增 `POST /api/wake`：以 `Authorization: Bearer <设备连接凭证>` 鉴权（与网页 Basic 认证共用恒定时间比较），只设置立即同步，供群晖“发送到相框”唤醒。实机验证：无凭证与错误凭证 401，正确凭证 202。
